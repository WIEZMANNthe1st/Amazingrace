# חפש את המטמון — משחק ברקודים לריבוי שחקנים

משחק מסלול לנייד: בכל תחנה מודבק ברקוד, השחקן סורק אותו, מקליד את הקוד, פותר חידה ומקבל את ההוראה לתחנה הבאה. עשרות קבוצות יכולות לרוץ במקביל, וטבלת דירוג חיה מסדרת אותן לפי סדר הסיום.

עמוד אחד, בלי שרת ובלי תלויות. הקובץ היחיד הוא `index.html`.

---

## 1. מסד נתונים (5 דקות, חינם)

הטבלה המשותפת צריכה מקום לשמור נתונים. משתמשים ב-Firebase Realtime Database.

1. היכנסו ל-<https://console.firebase.google.com> ולחצו **Add project**. שם כלשהו, אפשר לבטל את Analytics.
2. בתפריט הצד: **Build → Realtime Database → Create Database**. בחרו אזור, ואז **Start in test mode**.
3. העתיקו את כתובת המסד שמופיעה בראש הדף. היא נראית כך:
   `https://my-hunt-default-rtdb.europe-west1.firebasedatabase.app`
4. בלשונית **Rules** הדביקו:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

> הכללים האלה פתוחים לכל מי שמחזיק בכתובת. זה מתאים למשחק של יום אחד. אחרי האירוע מחקו את המסד (Project settings → Delete project) או החזירו את הכללים ל-`false`.

## 2. הדבקת הכתובת בקוד

פתחו את `index.html`, ובשורה הרביעית בערך הדביקו את הכתובת:

```html
<script>
  window.HUNT_DB_URL = "https://my-hunt-default-rtdb.europe-west1.firebasedatabase.app";
</script>
```

זו השורה היחידה שצריך לערוך בקובץ. (אם משאירים אותה ריקה, המשחק יבקש את הכתובת במסך הראשון ויזכור אותה רק בדפדפן הנוכחי — נוח לבדיקות, לא מתאים לשחקנים.)

## 3. העלאה לגיטהאב

```bash
git init
git add index.html README.md
git commit -m "Scavenger hunt"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

בלי טרמינל: פתחו ריפו חדש באתר גיטהאב, **Add file → Upload files**, וגררו את שני הקבצים.

## 4. הפעלת GitHub Pages

בריפו: **Settings → Pages → Source: Deploy from a branch → main / (root) → Save**.

תוך דקה־שתיים האתר יעלה בכתובת `https://USERNAME.github.io/REPO/`. זה הקישור שמחלקים לשחקנים.

## הפעלת המשחק

**מסך הניהול** — בתחתית כל מסך יש קישור "ניהול המסלול". קוד ברירת המחדל הוא `0000`, ומומלץ לשנות אותו שם מיד.

בפנים אפשר לערוך את שם המשחק, את החידות, את הקודים ואת ההוראות בין התחנות. כל תחנה יכולה להיות בכתיבה חופשית (מפרידים תשובות מתקבלות בפסיק) או בבחירה מתוך ארבע אפשרויות — אז סדר האפשרויות מתערבב אצל כל שחקן.

**ברקודים** — בתוך מסך הניהול יש "הדפסת הברקודים לתחנות". מדפיסים, גוזרים ומדביקים כל כרטיס בתחנה שלו. הברקוד מכיל את הקוד כטקסט בלבד, כך שהוא נסרק גם בלי קליטה ואי אפשר לדלג על תחנה.

**לפני סבב חדש** — "איפוס המרוץ" מוחק את כל השחקנים והתוצאות ומשאיר את החידות.

## טיפים לשטח

- תלו בנקודת הזינוק ברקוד נוסף של כתובת האתר עצמה, כדי שאף אחד לא יקליד כתובת.
- בדקו קליטה סלולרית בכל תחנה לפני האירוע. המשחק זקוק לאינטרנט כדי לעדכן את הטבלה.
- רוצו סיבוב ניסיון בעצמכם מהטלפון — זה חושף מיד חידה מעורפלת או הוראה לא ברורה.

## מבנה הנתונים

```
/course              — כל המסלול: תחנות, חידות, קודים, טקסטים
/runners/<id>        — שחקן אחד לכל מפתח: שם, זמן התחלה, תחנה נוכחית, זמן סיום
```

השחקן עצמו נשמר ב-`localStorage` של הדפדפן שלו, כדי שרענון הדף לא יאבד את ההתקדמות.
